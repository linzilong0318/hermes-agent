# 待澄清需求清单模板

> 本文档定义「待澄清需求清单」的 Markdown 模板。在阶段三基于确认后的需求和生成的用例，总结当前已确认的需求和仍不清晰的需求点。

---

## 模板

```markdown
# 待澄清需求清单

## 基本信息

| 项目 | 内容 |
|------|------|
| 批次号 | {batchNo} |
| Session ID | {sessionId} |
| 需求来源 | {PDF 文件名或下载链接} |
| 整理时间 | {yyyy-MM-dd HH:mm:ss} |
| 用例总数 | {N} 条 |

---

## 一、已确认需求

以下需求已经用户确认，已作为测试用例设计的依据：

| 编号 | 需求描述 | 优先级 | 确认状态 | 覆盖用例数 | 备注 |
|------|---------|--------|---------|-----------|------|
| REQ-001 | ... | 高 | ✅ 已确认 | 5 | ... |
| REQ-002 | ... | 中 | ✅ 已确认 | 3 | ... |

---

## 二、待澄清需求

以下需求点在需求文档中未明确，或在用例设计过程中发现存在模糊/遗漏之处，建议与需求方澄清：

| 编号 | 需求描述 | 疑问点 | 建议方案 | 影响范围 | 优先级 |
|------|---------|--------|---------|---------|--------|
| Q-001 | 环境名称的长度限制 | 文档未明确最大长度 | 建议限制 100 个字符 | 添加环境、编辑环境 | 高 |
| Q-002 | ... | ... | ... | ... | 中 |

---

## 三、需求覆盖度评估

| 指标 | 数值 |
|------|------|
| 功能点总数 | {N} |
| 已确认功能点 | {N} |
| 待澄清功能点 | {N} |
| 需求确认率 | {XX}% |
| 已确认需求覆盖的用例数 | {N} |

---

## 四、补充说明

- 本文档基于用户确认后的需求和生成的测试用例整理
- 建议在下一轮迭代中针对待澄清需求补充用例
- 如需求文档有更新，需同步更新本文档
```

---

## 使用说明

1. **已确认需求**：从阶段一中用户确认后的需求列表中提取，每条需求标注覆盖了多少条用例
2. **待澄清需求**：从以下来源汇总：
   - 阶段一中用户未明确确认的需求点
   - 用例设计过程中发现的边界不清晰、规则不明确的场景
   - 需求文档中前后矛盾或遗漏的内容
3. **覆盖度评估**：基于确认需求数和总需求数计算比例
4. **补充说明**：根据实际情况填写，没有可省略
